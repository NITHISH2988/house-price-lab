# Developer Guide: House Price Lab

This guide follows the implementation in `src/house_price_lab`. The default experiment uses generated data to verify the workflow; it is not a real housing study.

## Architecture and data flow

```text
data.make_dataset → train.train → split → candidate pipelines + CV
                                      ↓ choose by training-fold CV MAE
                               fit chosen pipeline → holdout metrics
                                      ↓
                        artifacts/model.joblib + metrics.json
                                      ↓
                      api.predict loads and applies pipeline
```

`data.py` creates deterministic feature columns and a synthetic target with a known formula and noise. `train.py` separates features from `price`, makes one 80/20 split, and runs five-fold cross-validation only on the 80% training partition. The candidate models are `DummyRegressor`, `Ridge(alpha=10)`, and `RandomForestRegressor`. `make_pipeline()` places numeric median imputation/scaling and categorical most-frequent imputation/one-hot encoding inside each estimator pipeline. That means each cross-validation fold learns preprocessing only from its own training fold. The winning candidate is refit on the full training partition and evaluated on the untouched holdout.

The report includes MAE, RMSE, R², residual summaries, CV MAE, and model-specific feature magnitudes. Absolute standardized Ridge coefficients and forest impurity importances describe model behavior; neither establishes causality. The fitted preprocessing and estimator are persisted together, so inference uses the same transformations as training.

## Directory map and entry points

- `src/house_price_lab/data.py`: `make_dataset(n, seed)` synthetic data source.
- `src/house_price_lab/train.py`: `make_pipeline`, `_feature_magnitudes`, `train`, and CLI `main`; run with `python -m house_price_lab.train`.
- `src/house_price_lab/api.py`: FastAPI app, `PropertyFeatures`, `/health`, and `/predict`; run with `uvicorn house_price_lab.api:app`.
- `tests/test_data.py`: generator determinism and data shape.
- `tests/test_training.py`: training artifacts and repeatability on a small synthetic sample.
- `tests/test_api.py`: request validation, health, artifact-backed predictions, and missing artifact behavior.
- `.github/workflows/ci.yml`: Python 3.11 setup, package install, Ruff, pytest, and runtime dependency audit.

## Reproduce a complete run

From the repository root in PowerShell:

```powershell
python -m venv .venv
.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
python -m pip install -e ".[dev]"
python -m house_price_lab.train --rows 1200 --seed 42 --output artifacts
python -m pytest -q
uvicorn house_price_lab.api:app --reload
```

The checked-in README records the observed synthetic run metrics; rerunning emits the full report and writes `artifacts/model.joblib` and `artifacts/metrics.json`. These artifacts are generated locally. A prediction request can be sent to `/predict` with:

```json
{"area_sqft": 1200, "bedrooms": 2, "age_years": 10, "location": "suburban", "property_type": "apartment"}
```

The API returns a `predicted_price` number. Its value is generated by the trained synthetic-data model and must not be interpreted as an estimate for a real property. `/docs` exposes the interactive OpenAPI page. The API currently loads `artifacts/model.joblib` from the process working directory; run Uvicorn from the repository root after training.

## Concepts to be ready to explain

1. **Leakage and pipelines:** preprocessing is fitted inside the CV estimator, so fold validation data cannot influence imputers, scales, or category encoding.
2. **Holdout versus cross-validation:** CV selects among candidates on training data; the test partition is used once for a final check.
3. **Baseline:** `DummyRegressor` tests whether learned structure improves over a constant mean prediction.
4. **Regularization and bias/variance:** Ridge shrinks coefficients; the forest can capture nonlinearities but its capacity depends on tree settings and data volume.
5. **Metrics:** MAE is in target units, RMSE penalizes large errors more, and R² compares residual variance with a mean baseline.
6. **Feature encoding:** one-hot encoding avoids imposing an artificial numeric order on location/property type.
7. **Model persistence:** saving the whole pipeline preserves preprocessing but joblib artifacts must be treated as trusted executable data.
8. **Explainability limits:** standardized coefficients and impurity importance are model-specific associations, not causal effects.

## Tests, CI, and extension points

Run `python -m pytest -q`, `python -m ruff check .`, and `python -m ruff format --check .`. CI repeats lint, formatting, tests, and `pip-audit` on GitHub-hosted Ubuntu. Tests use synthetic fixtures, so they establish workflow behavior rather than predictive quality on a housing market.

Good focused extensions include a licensed dataset adapter with documented provenance, a permutation-importance report on held-out data, and an API test that starts from a trained artifact. Before reporting real results, inspect the dataset license, define target units/population, preserve the holdout protocol, and record data version and seed. Do not tune against the final test set.

## Current limits and troubleshooting

- No licensed real dataset or genuine housing metric is included; California Housing was intentionally not adopted without a clear reuse grant.
- Synthetic features and target follow a hand-written equation, so high scores only show that the experiment code executes.
- If `/predict` returns 503, run the training command from the repository root and confirm `artifacts/model.joblib` exists.
- If `ModuleNotFoundError` occurs, activate the project virtual environment and install `-e ".[dev]`.
- If validation rejects a request, check the exact numeric bounds and allowed category spellings in `PropertyFeatures`.
